## 1. 文献调研：别人是怎么做的？

结论先说：**我们不是第一人**。"分诊式关卡 + 双专家"和"两阶段级联"是 ECG 边缘推理领域已经被验证过的常见范式，且"多任务量化退化"有专门文献研究（也就是本项目引用的 Rajotte 研究）。

| 文献 | 核心做法 | 与本项目关系 |
|------|----------|--------------|
| Rajotte et al., *Comparing Quantization Methods for On-Edge ECG Interpretation using Multi-Task CNN*（OpenReview） | 多任务 CNN 在 INT8 量化后性能显著退化，单任务模型更稳 | 本项目"双单任务专家而非多任务单模型"的直接理论依据 |
| *A Two-Stage ECG Classifier for Decentralized Inferencing Across Edge-Cloud Continuum*（IEEE Sensors J. 2024） | 两阶段：先"正常/异常"粗筛，再在边缘/云端分工细分类 | 与本项目"关卡→专家"同构 |
| *A Dual Stage Resource Efficient ECG Classifier*（IEEE） | 双阶段资源高效分类，第一阶段过滤正常拍，第二阶段才跑重模型 | 与本项目 §8.9 分诊式设计完全一致 |
| *A Cascaded Quantized Spiking Neural Network for Real-Time ECG Arrhythmia Detection on Edge Hardware*（MDPI Sensors 2026） | 级联量化脉冲网络，先轻量模型粗筛再重模型精判 | 证明级联思路在极低功耗端可用 |
| *Fusion-Based Deep Learning Ensemble on MIT-BIH and PTB-XL ECG Databases*（medRxiv 2025） | 在 MIT-BIH + PTB-XL 上做多模型融合 | 与本项目"双域双模型"目标一致 |
| *Dynamic Model Mixtures for Efficient AI Inference in Real-Time Biomedical Applications*（IEEE） | 动态模型混合，带两个 fail-safe | 与本项目"规则报警 + AI 报警"多层安全网同构 |

**文献启示总结**：
1. 两阶段/级联/门控是成熟范式，不是冒险；
2. 文献中第一阶段通常是"轻量级正常/异常分类器"，与本项目 §8.9.1 关卡模拟方向一致；
3. 多任务单模型在量化场景下风险高（Rajotte），双单任务专家方向正确；
4. 但文献大多只做 PC 端验证，**把"关卡+双专家"真正跑进 240MHz 单片机并在真实 AFE 上验收的，本项目在工程完整度上仍然少见**——这是我们的差异化价值。

## 2. 反思：当初双专家 OR 的问题本质

历史记录（§8.8）：双专家 OR（P2A + exp5_clean）在严谨口径下失败：
- MIT 正常拍误报率 25~32%；
- PTB 召回仅 0.41；
- 无单一阈值能同时满足双域。

**本质不是"双专家"这条路错了，而是四个具体问题叠加**：

| 编号 | 问题本质 | 证据 | 对策 |
|------|----------|------|------|
| E1 | **缺少"正常拍关卡"**：两个专家都是二分类器，各自都有正常拍误报，OR 后误报叠加 | §8.8 表：P2A 误报 21.6%，exp5 误报 10.9%，OR 后 25~32% | 增加"正常 vs 异常"关卡，正常拍不放行（§8.9 已验证 P 0.358→0.431） |
| E2 | **专家选错了**：exp5_clean 的患者级 PTB 能力已缩水（AUC 0.994→0.743），"心梗专家"名不副实 | §8.8 表：PTB-R 仅 0.41 | 心梗专家换成 **KD a070_t1**（AUC 0.836 / P 0.997 / 误报 0.4%） |
| E3 | **单门卫偏科**：用 P2A（MIT 域专家）当关卡时，对心梗拍给低分，误杀 PTB 召回（0.410→0.235） | §8.9.1 | 关卡模型必须是**双域训练的正常/异常分类器**，或"三分类关卡"（正常/心律失常/心梗分路放行） |
| E4 | **拍级 OR 没有时间确认**：单拍报警没有利用时间上下文，正常拍的偶发高置信就触发报警 | 固件已有 MULTI_BEAT_CONFIRM=5 机制 | 双专家输出同样走"连续 N 拍确认"的滞回计数器 |
| E5 | **任务粒度不匹配**：拍级专家直接对单拍输出，未聚合到"记录级/事件级" | PTB-XL 记录级验证 AUC 0.63~0.65 | 增加记录级聚合层（max/mean/p95 + 阈值），或"拍级报警 + 记录级诊断"双口径输出 |

**一句话总结**：当初否定的不是"双模型"，而是"**裸 OR + 错误专家 + 无关卡 + 无时间确认**"。把这四个问题修掉，双专家值得重试。

## 4. 完整验证链路

### 阶段 A：PC 侧离线验证（先不碰固件）

**A1. 关卡模型训练与选择**（是否重训：**是，必须重训**）

- 训练一个"正常 vs 异常"二分类关卡（输入 250 点窗口，与专家同结构 ResNet-Lite 或更小）。
- 训练数据：MIT-BIH + INCART 拍级标签（正常拍 vs 任意异常拍），**双域混合**：
  - 正常拍：MIT/INCART 的 N 类 + PTB 健康对照段正常拍；
  - 异常拍：MIT/INCART 异常拍 + PTB 心梗拍（解决 E3 单门卫偏科）。
- 验收标准：患者级口径，关卡误放行率 E_A ≤ 5%，异常保留率 Sn_A ≥ 95%（§8.9 设定）。
- 备选方案（若二分类关卡不过关）：三分类关卡（正常/心律失常疑似/心梗疑似），分路放行到对应专家。

**A2. 双专家 PC 模拟**

- 链路：窗口 → 关卡（正常则丢弃）→ 疑似异常 → 心律失常专家（P2A 或 exp7c）+ 心梗专家（KD a070_t1）→ OR/加权融合。
- 模拟三个候选心律失常专家（P2A / exp7c / exp6-SGD）× 关卡阈值网格。
- 评估口径：患者级 60/20/20 + 部署链数据（`_deploy` npz）+ MIT/PTB 双域。
- 产物：`dual_expert_triage_eval.json`（单模型基线 + 级联结果 + 阈值扫描）。

**A3. 时间确认与记录级聚合模拟**

- 拍级输出 → "连续 N 拍确认"滞回（N=3/5/7 扫描）。
- 记录级分数聚合：max / mean / p95 / abn_ratio，在 PTB-XL 记录级验证脚本上跑（`eval_ptbxl_record_level.py --superclass MI`）。
- 对比裸 OR（§8.8）与"关卡 + 时间确认"的 MIT 误报率、PTB 召回、PTB-XL AUC。

**A4. 决策门槛**

- 拍级：关卡阈值 + 专家阈值 + 确认拍数三参数联合扫描。
- 记录级：PTB-XL AUC ≥ 0.75（初步目标，低于 0.7 则放弃拍级专家直接做记录级模型）。
- 通过条件：MIT 正常拍误报 ≤ 5%（关卡后），PTB 召回 ≥ 0.6（心梗专家 KD 应可达），PTB-XL MI AUC ≥ 0.7。

### 阶段 B：INT8 量化与固件集成设计（是否重训：**模型不重训，量化导出即可**）

**B1. 量化导出**

- 对选中的 2 个模型（关卡 + 2 专家，或关卡 + 1 专家）分别走 `export_*.py` 流程导出 INT8。
- 量化损失验收：|ΔAUC| ≤ 0.01（项目既有标准）。
- 产物：`ecg_model_gate_int8.tflite`、`ecg_model_p2a_int8.tflite`（或 exp7c）、`ecg_model_kd_a070_t1_int8.tflite`。

**B2. Flash/SRAM 预算**（N16R8）

| 资源 | 单模型现状 | 三模型（关卡+双专家） | 结论 |
|------|-----------|----------------------|------|
| Flash（16MB） | 163.5KB | 3 × 167KB ≈ 500KB | ✅ 充裕 |
| SRAM Tensor Arena | 64KB | 分时复用 64KB（不并存） | ✅ 可行 |
| 推理时序 | 1 次/秒 | 关卡每 1s；专家仅在关卡触发时跑 | ✅ 平均开销可控 |

- 关键工程决策：**三模型不并存于 SRAM**，单个 TFLite Micro 解释器复用同一 64KB arena，按需切换模型（`tflite::GetModel(model_data)` 动态选择）。固件已有多模型头文件生成先例（`ecg_model_p2a_data.h` 等）。

**B3. 固件状态机设计**

```
每 1s 窗口：
  Core1 推送 → Core0
  Core0:
    1) 关卡模型推理（INT8）
       - score < gate_low  → 正常，丢弃，abnormal=0
       - score >= gate_low → 进入专家
    2a) 若关卡判"疑似心律失常"：跑心律失常专家
    2b) 若关卡判"疑似心梗"（或三分类关卡第三路）：跑心梗专家
    3) 专家异常概率 > 阈值 → 异常候选，进入连续确认计数器（MULTI_BEAT_CONFIRM）
    4) 连续 N 拍确认 → abnormal=1 + confidence
```

- 串口/BLE 输出增加专家来源字段（可选）：`abnormal,confidence,src`（src=0 正常 / 1 心律失常 / 2 心梗）。

### 阶段 C：板上部署与真机验证（是否重训：**否，烧录验证**）

**C1. 固件实现与编译**

- 修改 `ai_inference.cpp`：多模型选择 + 分诊状态机 + 确认计数。
- `pio run` 通过，RAM/Flash 不超限。

**C2. 板级离线验证（无需人体）**

| 输入 | 预期 |
|------|------|
| 模拟器（正常窦性 + 噪声） | abnormal=0，关卡全过滤 |
| 回放段 0（MIT-BIH 100 真实正常） | abnormal=0 |
| 回放段 1（MIT-BIH 106 VEB） | 心律失常专家报警 |
| 合成 VF/AF/停搏段（需先扩展回放数据） | 规则链 + 心律失常专家报警 |

**C3. 真实 AFE 三轮验收**

- 与历史标准一致：abnormal 全程 0，conf 全 0。
- 记录 AI 统计（总次数/异常次数/平均延迟）。

**C4. 端侧基准**

- 单次推理延迟：关卡 / 心律失常专家 / 心梗专家分别记录。
- 最坏情况（关卡触发 + 双专家全跑）延迟。
- INT8 一致性：PC TFLite vs 板上输出，逐窗口对比。

### 阶段 D：记录级与跨库验证（用什么样本验证）

| 数据集 | 粒度 | 验证内容 |
|--------|------|----------|
| MIT-BIH + INCART 测试集（患者级） | 拍级 | 心律失常召回、正常误报、AAMI 逐类 |
| PTB 测试集（患者级） | 拍级/记录级 | 心梗召回、正常误报 |
| PTB-XL（记录级，全量） | 记录级 | MI/STTC/CD/HYP vs 正常，AUC + 混淆矩阵 |

| 合成异常向量（VF/AF/停搏/过速/过缓） | 段级 | 规则链 + AI 互补验证 |
| 人体志愿实验（伦理后） | 记录级 | 静息/摆臂/踏步/深呼吸协议 |

## 6. 风险与回退

| 风险 | 概率 | 回退方案 |
|------|------|----------|
| 关卡模型达不到 E_A≤5% | 中 | 放宽到 10%，依靠时间确认补救；或三分类关卡 |
| 双专家分诊后 PTB 召回仍低 | 中 | 心梗专家改记录级模型（10s 窗口），拍级只做心律失常 |
| SRAM 紧张（分时复用复杂） | 低 | 只部署"关卡 + 单专家"，专家按模式切换（默认心律失常，用户手动切心梗筛查） |
| 板上延迟不达标 | 低 | 关卡用更小模型（CNN-tiny），专家只在关卡触发时跑 |
| 全链路收益不及单模型 | 中 | 回退单模型 exp7c（当前基线），保留记录级 PTB-XL 评估作为研究产出 |

## 7. 一句话结论

**双专家值得重试，但必须按"三分类关卡（或双域二分类关卡）+ 正确专家（P2A/exp7c + KD a070_t1）+ 连续确认 + 记录级聚合"来做，而不是重蹈"P2A + exp5_clean 裸 OR"的覆辙。**
