## 结论

主结果是**固件重放链**：500 Hz 重采样后走 `main.cc` 的梳状滤波 + `applyFilter`（0.5–40 Hz），
心率检测器每样本调用，VF 在偶数样本上调用，输入保持 mV，不乘 0.763（回放路径）。
拍位置用的就是这次 `hrProcess` 的 `beatDetected`。门控要先见过至少一拍（`s_beatEverSeen`），
并且报警窗结束时刻距最近一拍 **严格大于** 2500 ms，同时该窗 RMS ≥ 0.05 mV。

## 方法

### 固件在算什么

- 窗：1250 点，250 Hz，5 s，**不重叠**。窗满才算一次。`vf_detect.cpp` 写明不是滑动窗。
- 特征 6 维，与 `compute_features` 一致：去均值 RMS、`|x|` 中位数、4–10 Hz 能量比、带通后 `v>0` 过零率、局部峰个数/5、原始去均值信号过零率 ×125。
- 带通是固件里写死的 4 节 SOS，先正向再反向，**两遍都把状态清零**。
- 逻辑回归用头文件里的 mean/std/coef/intercept，θ = 0.15。连续两窗 `score ≥ θ` 才把 `vfAlarm` 置上。第一窗不会报。
- RMS 门：只看**这一窗**的 `lastRms ≥ 0.05`。
- 拍间门：`main.cc` 里 `s_beatEverSeen && (nowMs - s_lastBeatSeenMs) > 2500`。评测用 500 Hz 帧号，1 帧 = 2 ms，完成窗的帧是 `2500*(i+1)-2`。正好 2500 ms 不放行。
- 停搏/FLAT：见过拍之后，距最近一拍 ≥ 4000 ms 就成一段。这是附带结果，不拿来改 VF 阈值。

### 事件、窗、记录

参考节律只认 `.atr` 里符号为 `+` 的 `(...)` 标注，一段节律持续到下一次这类标注。
拍符号或 `~` 上碰巧带的 `(N` 不改节律。
CUDB 用 `[` 标 VF 起点、`]` 标终点，`]` 的 aux 是空的。`]` 结束可电击节律，并恢复进入 VF 之前的非可电击标注；文件里从没写过的话，尾段记为 `N`（括号外不是 VF）。`+ (VF` 和紧随的 `[` 算同一次起点，不拆成两段。
第一条节律标注如果不是从 0 秒开始，它之前的时间也记为 `N`：CUDB 说明里 VF 之前至少有 61 个非 VF 拍，`[` 只是大约的起点。整条记录一个节律标注都没有时保持 UNK，避免把缺标注的记录当成干净阴性窗。
可电击 token 只认整词：`VF`、`VFIB`、`VT`、`VFL`。`SVTA` 不是 VT。其余 token（`N`、`NOISE`、`ASYS`、`BI`、`PM`、`HGEA` 等）都当非可电击。
MIT-BIH 里成串的 `!`（室扑波）若没有被节律标注盖住，也算一段 VFL。

- **事件级（主结果）**：一段可电击节律时长 ≥ 10 s。两窗确认的最短几何长度就是 10 s；短于 10 s 的段另报，不进主分母。≥ 15 s 的段保证无论相位如何都能罩住两个完整 5 s 窗，也另报。
- 检出：任一被门控放行的报警窗与该段有时间重叠（不要求 50%）。
- **窗级**：窗内可电击时间 ≥ 50%，且噪声 < 50%，算阳性。噪声或未标注占多数的窗排除。停搏占多数的窗不进 VF 的灵敏度和假阳，单独交给 FLAT。
- **记录级**：记录里至少有一段 ≥ 10 s 可电击节律，且其中至少一段被检出。
- **假阳段**：连续报警窗并成一段，且整段都不与任何可电击参考重叠。FP/h = 假阳段数 / 分析小时。分析小时 = 完整窗数 × 5 / 3600，尾部不足一窗丢掉。
- 置信区间：比例用 Wilson；同时给**按记录重抽样**的 bootstrap 95% 区间（4000 次，种子 20261021），因为同一条记录里的窗和事件不独立。计数率另给 Poisson/χ² 区间。记录少、事件挤在少数记录里时，以 bootstrap 为准。

主结果的拍是固件 `heartrate.cpp`（内部 8–25 Hz，500 Hz）。
`main.cc` 只在 `filterInit()` 时清零，不调用 `filterWarmup()`，这里同样不清零，开头几秒有高通瞬态。

## 与固件逐项一致，以及和旧脚本的差

一致性测试通过：`True`。8 段合成窗上，Python float32 移植对编译后的 `compute_features` / 分数：
分数最大绝对差 5.96e-08，六维特征最大绝对差 rms 0, med_abs 0, vf_ratio 0, vf_zcr 0, pv_rate 0, dom_freq 0。
`vfProcess` 的报警位与「当前窗和上一窗都疑似」一致：True。
20 s、60 bpm 的窄脉冲上，链接进来的 `heartrate.cpp` 检出 19 拍。

上一版附件 `32_vf_rules_eval.py` 在同一批窗上和固件特征的最大绝对差：

| 特征 | 最大绝对差 |
|---|---:|
| rms | 4.632e-07 |
| med_abs | 2.98e-08 |
| vf_ratio | 0.3612 |
| vf_zcr | 0.0088 |
| pv_rate | 85.4 |
| dom_freq | 55.4 |

差集中在后四维：旧脚本把能量比做成了幅度比，过零用 `np.sign`（0 单独成一类），峰谷率数的是极值而不是峰，主频用的是带通后的过零而不是去均值原始信号。
另外，`scipy.signal.sosfiltfilt(..., padlen=0)` 相对固件零状态正反向滤波，波形最大绝对差 0.403。
scipy 即使 `padlen=0` 仍用 `sosfilt_zi` 做稳态初值；固件两遍都把状态清零。头文件里「等价 sosfiltfilt padlen=0」这句并不成立。

## 固件里对不上或值得单独看的点

这些是读源码和这次对照得到的，**没有改固件**。

- 部署路径是 5 s 不重叠窗。头文件里的「连续 2 窗、时延 ≤ 7.5 s」按 50% 重叠才成立；不重叠时第二窗结束最早在 10 s，相位不利时接近 15 s。
- `vfAlarm` 还要 `s_beatEverSeen`。一次会话如果从室颤开始、检测器又始终不报拍，VF 永远不会放行。`noarm` 列就是把这一条拿掉之后的数字。
- 2.5 s 门控看的是检测器的拍，不是病人是否真有脉搏。室颤波形若被当成 QRS，门控会在真 VF 上关闭。可电击段上的拍密度写在结果里。
- 注释写「等价 scipy sosfiltfilt padlen=0」。scipy 在 padlen=0 时仍用稳态初值 `sosfilt_zi`；固件正向、反向之前都把二阶节状态清零。一致性测试里量了这个差。
- `eval_vf_detect_v2.py` 训练时窗移是 2.5 s（50% 重叠），而且 MIT 对照没有从 360 Hz 重采样到 250 Hz 就按 1250 点切窗。头文件里的 VFDB Se 0.985 / CUDB Se 0.921 / MIT Sp 0.888 不是本报告这套协议，不能和这里的数字比。
- 真机 `vfProcess` 把重计算丢给 `vf_worker`。算不赢时会丢掉一整窗并把 `s_lastSuspect` 清零，两窗确认被打断。PC 走的是 worker 起不来时的同步分支，不模拟丢窗。
- 同步分支在窗的最后一个样本上把报警交出来；异步分支要等 worker 把结果塞回队列，门控时间戳会再晚几毫秒到若干采样。相对 2.5 s 可以忽略，但不是同一个采样点。
- AFE/模拟器路径把滤波后的样本乘 0.763 再送 VF；回放路径不乘。本评测按回放（输入已是 mV）。0.763 是为了把 AFE 的伏特量级拉回训练用的 mV，不是本实验要估计的增益。
- 旧 PC 脚本没有 2.5 s 门控，特征公式也和 `compute_features` 不一致。那次 VFDB 14/22、窗 Se 0.40、MIT 约 0.5 h 的数字作废。

## 不足

- 公开库通道 0 不是产品上的柔性单导联近似 Lead I。MIT-BIH 通道 0 多半是 MLII。导联不同，QRS 幅度和室颤形态都会变。
- 重放链的数字滤波器增益约 1，吃的是 mV。板上心率检测器是按 AFE 滤波后大约零点几伏标定的。mV 数值碰巧落在同一量级，但不是同一条模拟前端。QRS 相对标注的 Se/PPV 用来暴露这件事，不把它当成心率模块的正式成绩。
- 没有做 50 Hz 以外的工频模型。梳状滤波按固件固定在 500/10。美式记录里的 60 Hz 不会被这个梳状滤掉。
- NSTDB 只说明加噪后的假阳，不是室颤灵敏度。噪声段没有室颤参考。
- 事件重叠规则（只要沾到报警窗就算检出）对「晚 10 s 才响」仍然给真阳。延迟分布单独给了，临床能不能接受要看中位数，不能只看 Se。
- Wilson 区间把事件当独立样本，偏窄。报告里的 bootstrap 按记录重抽，记录数只有二十几条时区间仍然宽。
- 短于 10 s 的室速/室扑不在主分母里。它们在「不限时长」那一行，很多是窗长和确认规则从结构上盖不住的。
